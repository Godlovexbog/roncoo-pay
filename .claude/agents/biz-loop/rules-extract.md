## 提取方法行为与规则

读入口方法源码，提取结构化行为描述和内联业务规则。

### 输入
- 方法名 + 文件路径（来自规则发现清单）

### 步骤

1. **获取源码**: `context({name: "<methodName>", file_path: "<filePath>", include_content: true})`

2. **扫描决策点**: 遍历源码，标记所有决策位置
   - `if (条件) { throw new Xxx }` → 校验规则
   - `if (status == SUCCESS)` → 状态机规则
   - `switch/if-else` 多分支 → 路由规则
   - 金额相关计算+判断 → 资金规则
   - 每个决策点标注: 类型 / 源码行号 / 是否提取为规则 / 跳过原因

3. **提取方法目的**: 从方法注释 + 方法名 + 逻辑推断，用一句话说清做什么

4. **提取行为表**: 追踪方法的步骤流程
   | 步骤 | 做什么 | 输入 | 输出 |

5. **提取关联信息**:
   - GitNexus context 返回的 process 参与信息
   - 调用链中引用的 Entity/DTO/Enum
   - 调用的外部接口

6. **提取业务规则**: 对每个决策点，判定是否转为规则
   转为规则的条件:
   - 条件影响业务流程走向
   - 有明确的异常/拒绝/状态变更结果
   - 涉及业务数据校验或资金计算

7. **跳过条件**: 以下决策点不提取为规则
   - 纯日志打印
   - 纯技术性判断（如 null check 后 new 一个对象）
   - getter/setter（单行 return this.xxx 或 this.xxx = xxx）
   - 纯 DAO 委托（方法体只是 dao.xxx() 调用，无条件判断）
   - 纯技术工具（HTTP请求构造、XML/JSON解析、加密解密）

### 产出

`docs/biz-loop/panorama/rules/methods/<module>/<ClassName>/<methodName>.md`:

```markdown
# <methodName>

## 方法目的
(一句话)

## 方法行为
| 步骤 | 做什么 | 输入 | 输出 |
|------|--------|------|------|

## 关联
- GitNexus Process: <id>
- 实体: [链接到 data-model.md]
- 接口: [链接到 api-list.md]

## 业务规则

### R-001 <规则名>
- **条件**: <if 条件>
- **动作**: <then 动作>
- **类型**: 校验/路由/状态机/资金

## 提取质量

| 指标 | 值 |
|------|-----|
| 源码行数 | N |
| 发现决策点 | M (if Y + throw Z + switch W + 金额计算 X) |
| 提取为规则 | K |
| 合理跳过 | S (日志打印 / 技术判断 / 空值初始化) |
| 决策点→规则转化率 | K/(M-S) × 100% |
| 置信度 | 0.0-1.0 |

> 置信度标准:
> - 1.0: 所有决策点都有明确的异常码/状态变更/业务影响
> - 0.8-0.9: 部分决策点缺乏显式异常码, 但逻辑清晰
> - 0.5-0.7: 代码逻辑复杂, 部分规则推断成分较多
> - <0.5: 需人工审核
```
